# 케로로 인터랙티브 웹 — 슬라이드별 발표 대본

기존 03번 ‘역할을 나누면 코드가 단순해진다’를 제외한 **13장 구성**입니다. 기존 04~14번은 03~13번으로 당겼습니다. **‘발표 대본’ 문단만 읽고**, 코드 설명이 더 필요하면 [코드 해설과 예상 질문](presentation-code-notes.md)을 참고하세요.

8주차 발표 안내는 최대 5분입니다. 아래 시간은 **설명 4분 30초 + 시연 30초**를 목표로 잡은 연습용 배분입니다. 실제 낭독 측정값은 아니므로 연습하면서 확인하세요. 추가 개념도 발표 대본 안에서 기능과 사용 이유를 설명합니다. 각 장의 ‘코드 확인’은 연습용 보충 설명이며, 전부 읽을 필요는 없습니다.

‘수업 개념’은 제공한 Notion의 2~8주차 강의 슬라이드와 공개 예제에서 확인한 내용입니다. ‘추가 개념’은 그 자료에서 확인되지 않은 기능을 뜻합니다. 수업 시간에 구두로 다룬 내용까지 판단한 표시는 아닙니다. 주차별 근거는 [코드 해설의 출처 표](presentation-code-notes.md#수업-자료와-구분-기준)에 정리했습니다.

**목표 시간: 15초 · 바깥 `div` → `button` → `img` 가리키기**

**발표 대본**

“수업의 부모·자식 구조를 이용해 캐릭터를 세 겹으로 나눴습니다. 바깥 div는 등장할 때 이동하고, 버튼은 위아래로 떠 있는 동작을, 이미지는 클릭 반응을 맡습니다. 이렇게 나누면 각 움직임을 따로 조절할 수 있습니다.”

**수업 개념:** HTML 요소의 부모·자식 관계, 이미지 경로, 클래스. 2~3주차.

## 04. 화면 비율에 맞춰 포스터를 재배치

**목표 시간: 25초 · 기본 배치와 세로 화면 코드 비교하기**

**발표 대본**

“위치는 수업에서 배운 absolute와 left, top으로 정했습니다. 추가한 미디어 쿼리는 화면 조건에 따라 다른 CSS를 적용하는 기능입니다. 세로 화면에서는 배치를 바꿉니다. cqw와 cqh는 장면 너비와 높이의 1퍼센트를 나타내는 단위이고, min 함수는 두 크기 중 작은 값을 골라 이미지가 너무 커지지 않게 합니다.”

**수업 개념:** `position`, `left`, `top`, 크기와 CSS 적용 순서. 3주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`container-type: size`**: 장면을 크기 기준 컨테이너로 지정합니다. 내부 이미지가 장면 크기를 참조하게 합니다.
- **`cqw / cqh`**: 컨테이너 너비·높이의 1%를 뜻합니다. 이 코드에서는 브라우저 전체가 아니라 장면 크기가 기준입니다.
- **`min(56cqw, 70cqh)`**: 장면 너비의 56%와 높이의 70% 중 작은 값을 이미지 너비로 고릅니다.
- **`@media`**: 너비·방향 등의 조건이 맞을 때만 안쪽 CSS를 적용합니다.
- **`translate: -50% -50%`**: 자기 상자의 절반만큼 왼쪽·위로 옮겨 left·top 지점에 이미지 중심을 맞춥니다. 수업의 이동 변형을 독립 속성으로 쓴 추가 문법입니다.

## 05. 6.1초 안에 쌓아 올리는 등장 순서

**목표 시간: 25초 · 시간 막대의 시작점과 겹치는 구간 가리키기**

**발표 대본**

“수업의 animation-delay로 캐릭터마다 출발 시간을 다르게 줬습니다. 추가한 CSS 변수는 값에 이름을 붙여 저장하는 기능입니다. 예를 들어 flight에 비행 시간 1.25초를 저장하고, var로 꺼내 씁니다. 그래서 공통 동작을 유지하면서 캐릭터별 시간만 바꿀 수 있습니다. 마지막 캐릭터가 도착한 뒤 타이틀이 나옵니다.”

**수업 개념:** `@keyframes`, 애니메이션 시간·지연·채우기 모드. 4주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`--flight: 1250ms`**: 비행 시간을 이름 붙여 저장한 CSS 사용자 정의 속성입니다.
- **`var(--flight)`**: 저장한 값을 해당 위치에 넣습니다. JS에서 변수를 선언하는 var와는 다른 문법입니다.
- **`--delay`**: 캐릭터별 출발 시점을 저장합니다. 하나가 끝나기 전에 다음이 출발해 움직임이 겹칩니다.

## 06. 출발점은 언제나 모니터의 중심

**목표 시간: 25초 · `origin.x - x` 가리키기**

**발표 대본**

“모니터에서 출발시키려면 실제 위치를 알아야 합니다. 추가로 쓴 getBoundingClientRect는 화면에 표시된 요소의 위치와 크기를 읽는 함수입니다. 여기서 모니터 중심을 구하고 캐릭터의 최종 위치를 빼면, 시작할 때 옮겨야 할 거리가 나옵니다. 이 값을 CSS 변수로 전달하고 창 크기가 바뀌면 다시 계산합니다.”

**수업 개념:** 좌표, 변수, 크기 읽기, `.css()`. 5~7주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`getBoundingClientRect()`**: 요소 상자의 화면 좌표와 크기를 읽습니다. 장면의 좌표를 빼서 같은 기준으로 맞춥니다.
- **`parseFloat()`**: 단위가 붙은 문자열에서 숫자를 꺼냅니다. 예를 들어 600px에서 600을 읽어 계산합니다.
- **`.each()`**: 캐릭터 각각에 같은 계산을 반복 적용합니다.
- **`resize`**: 창 크기 변경을 감지하는 이벤트입니다. 모니터 위치가 바뀌면 출발 좌표도 다시 계산합니다.

## 07. 작게 출발해서 화면 앞으로 돌진

**목표 시간: 25초 · 출발 → 확대 → 안착 순서로 가리키기**

**발표 대본**

“수업의 keyframes와 transform으로 작게 출발해서 커졌다가 제자리에 오게 했습니다. 여기에 추가한 perspective는 가까이 온 이미지가 더 크게 보이게 하는 원근 설정입니다. translate3d는 가로·세로에 깊이 방향 이동까지 더합니다. 캐릭터를 화면 앞으로 당기고 기울여 튀어나오는 느낌을 냈습니다. 평면 이미지를 변형한 효과입니다.”

**수업 개념:** `@keyframes`, 이동·회전·확대, `opacity`. 4주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`perspective(900px)`**: 깊이 차이가 화면에서 크기 차이로 보이도록 원근 투영을 적용합니다.
- **`translate3d(x, y, z)`**: 세 방향의 이동을 지정합니다. 여기서는 z가 320px인 구간에서 이미지가 화면 앞쪽에 옵니다.
- **`rotateX / rotateY`**: 이미지를 앞뒤·좌우로 기울이는 3D 회전입니다.
- **`calc()`**: CSS 안에서 계산합니다. 캐릭터별 회전값에 비율을 곱해 기울기를 조절합니다.

## 08. 재생 상태를 클래스 하나로 연결

**목표 시간: 25초 · 조건문 다음 CSS 정지 코드 보여주기**

**발표 대본**

“수업의 클릭 이벤트와 조건문으로 현재 상태에 맞게 버튼을 처리합니다. 추가한 animation-play-state는 애니메이션을 없애지 않고 현재 위치에서 멈추는 속성입니다. 정지 클래스를 빼면 이어서 움직입니다. 처음부터 다시 재생할 때는 클래스를 지우고 offsetWidth로 화면 계산을 한 번 반영한 뒤 다시 붙입니다.”

**수업 개념:** `.on()`, 함수, 변수, `if/else`, 클래스 추가·제거. 5~6주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`animation-play-state: paused`**: 현재 애니메이션의 진행을 멈춥니다. 지우지 않았으므로 이어서 재생할 수 있습니다.
- **`offsetWidth`**: 요소 너비를 읽는 속성입니다. 여기서는 값 자체보다, 클래스가 제거된 상태의 레이아웃 계산을 반영시키는 데 사용합니다.
- **`animationend`**: CSS 애니메이션이 끝날 때 발생하는 이벤트입니다. 진행 막대가 끝나면 완료 상태로 바꿉니다.

## 09. 같은 클릭, 서로 다른 캐릭터 반응

**목표 시간: 15초 · 공통 클릭 코드와 `--reaction` 연결하기**

**발표 대본**

“클릭 처리 코드는 공통으로 썼습니다. 추가로 쓴 find는 선택한 요소 안에서 원하는 요소를 찾는 메서드입니다. 클릭한 버튼 안의 이미지를 찾아 반응 클래스를 붙입니다. CSS 변수에는 동작 이름을 저장해서 타마마는 뛰고 케로로는 경례하게 했습니다.”

**수업 개념:** 클릭 이벤트, 조건문, 클래스, 애니메이션. 4~6주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`.find('img')`**: 클릭한 버튼 내부에서 이미지 요소를 찾습니다.
- **`.closest('.character')`**: 자신부터 부모 방향으로 올라가며 가장 가까운 캐릭터 상자를 찾습니다. 파티클 위치와 색을 읽는 데 씁니다.
- **`--reaction: jump`**: 애니메이션 이름을 저장합니다. 자식 이미지가 이 값을 받아 어떤 동작을 할지 정합니다.
- **`cubic-bezier()`**: 시간에 따라 움직임이 빨라지고 느려지는 곡선을 지정합니다. 클릭 반응의 속도감을 조절합니다.

## 10. 별·원·색종이도 HTML과 CSS로

**목표 시간: 25초 · 생성 → 이동 → 정리 순서로 설명하기**

**발표 대본**

“파티클의 움직임은 수업의 CSS 애니메이션으로 만들었습니다. 추가한 for 반복문은 같은 작업을 여러 번 실행해서 작은 span을 만듭니다. Math.random은 무작위 값을 뽑아 퍼질 방향과 거리를 다르게 합니다. cos와 sin은 그 방향을 가로·세로 이동량으로 바꿉니다. 만든 요소는 화면에 추가하고, 효과가 끝나면 삭제합니다.”

**수업 개념:** HTML 요소, CSS 모양·색상·애니메이션, 배열. 2~6주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`$('<span>') / .appendTo()`**: 새 HTML 요소를 만들고 파티클 묶음 안에 넣습니다. 이처럼 JS로 화면 요소를 만들거나 바꾸는 것이 DOM 조작입니다.
- **`for / i % 3`**: 정한 개수만큼 생성 작업을 반복합니다. 나머지 연산으로 0·1·2를 반복해 세 모양을 번갈아 고릅니다.
- **`Math.random()`**: 0 이상 1 미만의 난수를 만듭니다. 파티클이 매번 조금씩 다르게 퍼지게 합니다.
- **`Math.cos() / Math.sin()`**: 각도와 거리를 X·Y 방향 이동량으로 나눕니다.
- **`clip-path: polygon()`**: 여러 꼭짓점을 연결한 모양으로 요소를 잘라 별을 만듭니다.
- **`animationend / .remove()`**: 종료를 감지하고 묶음을 삭제합니다. 연속 클릭 때는 최대 여섯 묶음만 유지합니다.

## 11. 마우스와 소리로 반응을 더한다

**목표 시간: 30초 · 마우스 좌표 식 → 오디오 코드 가리키기**

**발표 대본**

“7주차 좌표 예제에 추가 계산을 넣었습니다. 마우스 위치를 화면 중앙 기준의 작은 이동량으로 바꾸고, 캐릭터마다 다르게 곱해서 앞뒤에 있는 듯한 시차 효과를 냈습니다. pointermove는 포인터 이동 이벤트이고, 종류를 확인해 마우스에만 반응시킵니다. 소리에서는 currentTime을 0으로 해 처음으로 돌리고 play로 재생합니다. catch는 재생 실패를 처리하는 부분입니다.”

**수업 개념:** 마우스 좌표, `.width()`, `.height()`, `.css()`는 7주차; `<audio>` 태그는 2주차.

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`.offset()`**: 장면이 문서 안에서 어디에 있는지 읽습니다. 마우스 좌표에서 빼면 장면 안의 좌표가 됩니다.
- **`좌표 정규화`**: 장면 크기로 나눠 0~1 범위로 만든 뒤 0.5를 빼 중앙을 0으로 맞춥니다. 작은 수를 곱해 조금만 움직이게 합니다.
- **`--depth`**: 이동량에 곱할 값을 캐릭터별로 저장합니다. 실제 3D 거리 측정값은 아닙니다.
- **`pointermove / pointerType`**: 포인터 이동과 입력 종류를 확인합니다. 터치에는 마우스 시차 이동을 적용하지 않습니다.
- **`currentTime / play()`**: 오디오 재생 위치를 정하고 재생을 요청합니다.
- **`Promise / .catch()`**: 재생 요청처럼 결과가 나중에 정해지는 작업의 실패를 받습니다. 실패하면 효과음 버튼 상태를 갱신합니다.

## 12. 재생 도구와 입력을 안정적으로 제어하기

**목표 시간: 30초 · 추가 개념을 기능 중심으로 설명하기**

**발표 대본**

“환경에 대응하는 기능도 추가했습니다. prefers-reduced-motion은 기기의 동작 줄이기 설정을 읽는 조건입니다. 이때는 완성 화면을 바로 보여줍니다. load와 error로 이미지 준비와 실패를 확인하고 최대 10초만 기다립니다. inert는 등장 중인 영역의 입력을 막고, aria-label은 화면 읽기 도구에 버튼 이름을 알려줍니다. visibilitychange로 탭이 안 보이게 된 것을 감지하면 정지합니다.”

**코드 확인 — 추가 개념을 쉽게 풀면**

- **`prefers-reduced-motion`**: 큰 움직임을 줄이려는 사용자 설정에 맞춰 CSS를 적용하는 조건입니다.
- **`matchMedia()`**: 같은 조건이 현재 맞는지 JS에서 확인합니다. 등장 효과를 건너뛸지 결정합니다.
- **`load / error / setTimeout()`**: 이미지의 준비·실패를 감지하고 기다릴 시간을 제한합니다. 실패한 이미지를 복구하는 기능은 아닙니다.
- **`inert`**: 영역의 클릭·키보드 초점 등 상호작용을 막습니다. 등장 중인 캐릭터와 타이틀에 적용합니다.
- **`aria-label / aria-pressed`**: 보조 기술에 버튼의 이름과 켜짐·꺼짐 상태를 전달합니다.
- **`:focus-visible`**: 키보드 등으로 초점을 표시할 필요가 있을 때 버튼 테두리를 보여줍니다.
- **`visibilitychange`**: 문서 표시 상태가 바뀌면 발생합니다. 다른 탭으로 가면 정지하며, 돌아왔다고 자동으로 재생하지는 않습니다.

## 13. 효과별로 수정할 코드 찾기

**목표 시간: 10초 + 시연 약 30초 · 코드 파일 표에서 실제 웹으로 전환하기**

**발표 대본**

“위치와 크기는 styles.css, 움직임은 animations.css, 클릭과 재생 제어는 main.js에서 수정합니다. 마지막으로 재생과 클릭 반응을 보여드리겠습니다.”

**시연 순서**

1. **다시 출동**을 누른 뒤 등장 중에 잠깐 정지하고, 다시 눌러 이어서 재생합니다.
2. 등장 완료 후 **타마마와 케로로를 한 번씩 클릭**해 반응이 다른 것을 보여줍니다.
3. **마우스를 좌우로 이동**해 캐릭터의 작은 움직임을 보여줍니다.
4. 시간이 남으면 세로 화면을 보여줍니다. 효과음은 장소에 맞춰 선택합니다.

캐릭터 클릭은 등장 완료 뒤에 해야 반응합니다. 시연 중 창 크기를 바꾼다면 다시 출동을 눌러 새 화면 크기에 맞춘 등장 경로도 보여줄 수 있습니다.

발표를 마칠 때: “이상으로 발표를 마치겠습니다. 감사합니다.”
